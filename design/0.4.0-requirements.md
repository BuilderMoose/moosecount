# moosecount 0.4.0 — One Library, Two Tools, Machine-Readable Output

## Why

Two problems that turn out to be the same problem.

**Nothing consumes the output.** Both tools print a table for a human. There is
no way to track lines over time, feed a dashboard, or assert in CI that a
module has not doubled in size.

**moosemetrics has none of the ignore work.** Its `--exclude` takes a bare
folder name and nothing else: no wildcards, no anchoring, no negation, no
`.gitignore` discovery. The two tools ship together, share a flag name, and
mean different things by it. That gap widens every time moosecount improves.

It also has no tests, and no way to get any without introducing a third testing
idiom to the repository.

0.3.0 moved the counting work into `MoosecountLib` so the tests could link it.
The same move solves this: moosemetrics becomes a second binary against that
library rather than a separate program that has to re-derive everything.

```
MoosecountLib      ignore rules, traversal, renderers
  |-- moosecount       counts code
  `-- moosemetrics     counts documents
```

Two tools, as designed. One implementation of the parts that are hard.

## Goals

- moosemetrics inherits every ignore rule by linking, not by copying.
- Both tools emit JSON that a script can consume without scraping.
- Document counting becomes unit-testable, like code counting already is.
- Neither tool's human-readable output changes.

## Non-goals

- Parallel traversal. Still premature.
- New languages. Cheap to add now, but not this release's theme.
- Any change to the ignore rules themselves.

## Considered and rejected

**moosemetrics calls moosecount as a subprocess.** The first draft of this
document specified it, and writing it out is what ruled it out. It needed a
`--list-files` flag on moosecount existing solely for moosemetrics' benefit,
binary discovery through an environment variable and `PATH`, a serialization
boundary that cannot represent a filename containing a newline, and a breaking
change where moosemetrics stops working unless moosecount is installed. All
four disappear when the rule engine is called rather than piped.

**One binary with a `--docs` mode.** Gets the same reuse, but gives up the
two-tool split for no gain.

## Document analysis

Markdown and PlantUML do not fit `LanguageSpec`. Their metrics differ in kind —
words, headers, open versus completed tasks, UML entities and relationships,
rather than code, comment and blank. So this is a sibling of the language
parser, not another row in its table.

```
DocumentTotals
  lines, words, headers, openTasks, completedTasks    (markdown)
  lines, umlEntities, relationships                   (plantuml)

DocumentKind   Markdown (.md .txt) | PlantUml (.puml .pu .wsd)
```

The counting rules carry over from `moosemetrics.py` unchanged, so the numbers
do not move:

- headers: lines matching `^#{1,6}\s`
- tasks: `^\s*-\s*\[ \]` open, `^\s*-\s*\[xX\]` completed
- words: whitespace-separated runs
- UML entities: `class|component|actor|usecase|state|node|interface` at line
  start, case-insensitive
- relationships: `-->`, `..>`, `<|--` and the other arrow forms

These are line-oriented scans, not parsing. Hand-scanning beats `std::regex`
here on both speed and legibility.

## Shared command line

Both tools accept `--exclude`, `--ignore-file`, `--gitignore`, `--ext`,
`--no-defaults`, `--sort`, `--json`, `--help` and `--version`. Parsing those
twice is the same trap as implementing the ignore rules twice, so option
parsing moves into the library and each binary supplies only what is specific
to it. `--version` then reports one number for both, from `CMakeLists.txt`.

## JSON

```json
{
  "schemaVersion": 1,
  "tool": "moosecount",
  "version": "0.4.0",
  "totals": {
    "files": 17, "linesOfCode": 496,
    "code": 335, "format": 161, "comment": 41, "blank": 70, "total": 605
  },
  "languages": [
    { "name": "C/C++", "files": 12, "linesOfCode": 420,
      "code": 300, "format": 120, "comment": 38, "blank": 60, "total": 518 }
  ],
  "files": [
    { "path": "src/parser.cpp", "language": "C/C++", "linesOfCode": 302,
      "code": 210, "format": 92, "comment": 25, "blank": 40, "total": 367 }
  ],
  "warnings": [
    { "kind": "unmatchedRule", "rule": "tetss",
      "message": "--exclude \"tetss\" matched nothing" }
  ]
}
```

moosemetrics emits the same envelope — `schemaVersion`, `tool`, `version`,
`totals`, `files`, `warnings` — with document fields in place of language ones,
so one consumer can read both.

Notes on the shape:

- **`schemaVersion` is deliberate.** One integer now, and a consumer is not
  left guessing later.
- **Per-file totals are full**, not just the `linesOfCode` the text output
  prints. The walker currently keeps `code + format` per file and throws the
  rest away; it will keep the whole `CountTotals`. Same work, more retained.
- **Warnings appear in both places**: still on stderr, and repeated in the
  document, because a CI job capturing only stdout would otherwise lose them.
- Ordering matches the text output — by path, or by count under `--sort`.
  Deterministic output is the point of emitting it at all.

JSON is written by hand. The document is a fixed shape and a dependency for one
serializer is not worth it. Escaping gets its own unit tests, since paths carry
quotes and backslashes on some platforms.

## Decisions to confirm

**D1. `moosemetrics.py` is deleted, not kept alongside.** Recommend **deleted
in the same commit**. A retained copy drifts, and the whole point is one
implementation. `make install` copies a second binary instead of a script.

**D2. moosemetrics' output format does not change.** Recommend **unchanged** —
same table, same totals block, same wording. There is no reason to churn the
one surface you actually read, and keeping it steady makes the rewrite
verifiable against the current script.

**D3. Warnings under `--json` go to both stderr and the document.** Slight
duplication; neither consumer loses them.

**D4. Text output stays the default.** `--json` is additive. Anything scripting
against the text output today keeps working.

## Compatibility

- moosecount's text output is unchanged; `--json` is new.
- moosemetrics produces the same numbers and the same table, from a binary
  rather than a script. Its `--exclude` becomes far more capable, and it gains
  `--gitignore`, `--ignore-file`, `--ext`, `--no-defaults` and `--sort`.
- `make install` installs two binaries. Anyone invoking `python3
  moosemetrics.py` directly needs `make build` first.
- Default document extensions stay `.md`, `.txt`, `.puml`, `.pu`, `.wsd`, and
  moosemetrics' current default exclusions (`build`, `bin`, `.git`, `.vscode`)
  are preserved as its built-in rules.

## Architecture

```
src/
  options.hpp/.cpp     shared flag parsing, help, version
  report.hpp/.cpp      renderText(), renderJson() for both tools
  document.hpp/.cpp    DocumentTotals, the markdown and puml scanners
  walker.hpp/.cpp      grows a document mode alongside the counting one
main.cpp               moosecount CLI
metrics_main.cpp       moosemetrics CLI
```

`CountReport::files` grows from `{path, displayLines}` to carrying the full
`CountTotals` and the language name.

The walker already does the hard part — traversal, ignore rules, per-extension
dispatch. It gains a second mode that runs document scanners instead of the
line counter, rather than being duplicated.

## Testing

- Document scanners get the treatment the language parsers got: source in
  memory, expected metrics out, one case per construct — nested task lists,
  `#` inside a fenced code block, arrow forms, entity keywords.
- Renderer tests: a known report in, exact text or JSON out. Escaping gets its
  own cases.
- Integration: `--json` parsed with Python's `json` module and asserted against
  the same fixture trees the text tests use, so both renderers are held to the
  same numbers.
- A fixture tree of markdown and PlantUML under an ignore file, asserting
  moosemetrics inherits the rules rather than approximating them.
- Before deleting `moosemetrics.py`, run both over this repository and diff the
  output. They must agree exactly.
